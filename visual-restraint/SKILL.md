# visual-restraint

## Intent

Practice restraint: contribute only the visual decisions required by the brief, the established system, or the user's direction. Produce a neutral scaffold that leaves visual authorship with the user.

Restraint limits unsolicited authorship, not visual expression. An explicitly expressive, decorative, or maximalist direction should remain so.

## Protocol

1. Establish visual authority.
   - Within functional and accessibility constraints, rank explicit direction and supplied references first, then the existing product or design system.
   - Treat open visual choices as deferred.
   - When modifying a product, inspect the surrounding interface before choosing styles.
   - Complete when the sources of authority and the open visual decisions are clear.

2. Build the scaffold.
   - Establish content hierarchy, reading order, layout, and interaction before adding personality.
   - Reuse existing primitives. Where none exist, use native or system defaults and the fewest visual concepts needed for clarity.
   - Keep open choices quiet, conventional, and easy to replace.
   - Complete when hierarchy and interaction carry the result end to end.

3. Apply earned styling.
   - Create hierarchy with content order, spacing, alignment, and typography first.
   - Group by proximity; introduce a container when it communicates a real boundary, state, or interaction.
   - Use color for meaning or deliberate emphasis, depth for actual layers, and motion for state or spatial change.
   - Follow supplied visual direction faithfully, including choices that exceed the neutral baseline.
   - Complete when every agent-authored style has a functional or hierarchical purpose.

4. Run a subtraction pass.
   - For each visual rule the agent introduced, name its purpose and consider the result without it.
   - Remove it when deletion preserves hierarchy, usability, and directed identity.
   - Return nested surfaces to the simplest meaningful structure and collapse competing treatments into one.
   - Complete when every remaining choice is directed, inherited, or required by the interface.

## Neutral Baseline

Use this only where neither the user nor the existing system has decided:

- Inherited or system typography with a restrained scale.
- A flat page plane with boundaries only where structure needs them.
- Neutral color plus semantic color for interaction and state.
- Platform or design-system controls with complete states and visible focus.
- Images, icons, effects, and motion only when they carry information or the direction calls for them.

## Rules

- Spend detail on behavior, responsiveness, accessibility, and content before visual personality.
- Preserve distinctive choices from references; the neutral baseline governs only open decisions.
- A rough, honest scaffold is better than speculative polish.
- Surface consequential open visual decisions at handoff.
